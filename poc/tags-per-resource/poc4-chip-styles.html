POC 4 — seven looks for the same thing. POC 1's placement (tags live in the entry line) is kept; only the visual treatment varies here. All seven share identical markup, so whichever you pick is a pure CSS swap — the implemented Tags-page grouping (POC 1) and the live filter (POC 2) work the same in every style. Same five entries per section (9Ghz, Have I Been Pwned, theHarvester, SpiderFoot, Maltego — real + sample as in POC 1); hover chips where interactive, hover whole rows in F. Which energy do you want the list to have?

Tag styles for per-resource tags

Type chips carry a ◆ marker except where noted. Green pill = platform/tech tag.

F · Hover reveal — tags only when asked

Collapsed to a ⋯ 5 peek; hovering or keyboard-focusing the row expands the chips (touch devices always see them). Cleanest possible list, but you can't see what something is tagged without aiming at it — weakest discovery, and the filter toolbar becomes the primary way in. Hover a row to try.

G · Badge row — tags join the CI pills

Tags use the exact geometry of the ★/last-commit badges and sit in one metadata row before them: amber = type (same family as stars), sky-blue = tech, emerald = platform. Reads as one data strip; risk of feeling like everything is a badge if the list grows colorful.

  • SpiderFoot — OSINT automation for footprinting and risk profiling targets. toolosintautomation ★ 15klast commit 3y 44d
  • Maltego — Proprietary link-analysis platform for mapping OSINT entities. toolosintgraphproprietary
Recommendation (not a decision for me to make alone): D or G for scannability once pages get tag-dense; B/C if you want the list prose-first. A stays the safe baseline; F is the most minimal but costs discovery. Markup and behavior are identical across all seven, so this is purely about look — say which and it lands in theme.css only.
